# Amnezia Browser

Версия **1**. Расширение направляет выбранные домены Chrome через локальный mihomo с конфигом Amnezia/WireGuard. Это независимый неофициальный проект, не связанный с AmneziaVPN.

## Установка и обновление

Распакуй весь архив в постоянную папку. Для обновления сначала экспортируй правила в настройках старого расширения. Повторная установка backend сохраняет существующий ключ подключения. Manifest version и публичный ключ расширения сохранены; версия не увеличивалась.

Нужны Chrome/Chromium 120+, конфиг с одним Interface и одним Peer, свободные локальные порты 1080 и 9090 и доступ к GitHub для загрузки ядра. Поддерживаются Windows AMD64/ARM64 и Linux x86_64/aarch64. Используется mihomo v1.19.30 с проверкой закреплённой SHA-256.
На Windows WireGuard/AmneziaWG принудительно использует mihomo IP stack (`mips`) с `bbr`. В A/B-тесте на сборке mihomo v1.19.30 `with_gvisor` автоматический выбор gVisor давал аномально низкий upload; `mips + bbr` восстановил upload до уровня Direct. Linux не переключается автоматически, поскольку там этот эффект не проверялся.

### Windows

Открой PowerShell в распакованной папке и выполни:

```powershell
.\install.ps1 -ConfigPath "C:\path\amnezia.conf"
```

Без аргумента установщик откроет выбор файла. Установка выполняется для текущего пользователя в `%LOCALAPPDATA%\AmneziaBrowser`. Скрипт не меняет ExecutionPolicy; действующая политика Windows должна разрешать запуск локальных скриптов.

Права на папку и файлы ограничиваются текущим пользователем, SYSTEM и локальными администраторами. Установщик меняет только список прав доступа (DACL), сохраняя владельца, группу и настройки аудита (SACL); `SeSecurityPrivilege` для этой операции не запрашивается. Файлы, владелец которых не входит в этот набор, отклоняются.

### Linux

Нужны Bash, curl, awk, gzip, coreutils, util-linux (flock) и iproute2 (ss). Запускать без sudo:

```bash
bash install.sh "/path/to/amnezia.conf"
```

Ядро и менеджер: `~/.local/lib/amnezia-browser`. Конфиг и ключ подключения: `~/.config/amnezia-browser`. Автозапуск через desktop entry работает при входе в поддерживающую его графическую сессию.

### Подключение расширения

1. Открой `chrome://extensions`, включи режим разработчика, выбери «Загрузить распакованное расширение» и папку `extension`. При обновлении замени файлы прежней папки и нажми «Обновить» у расширения.
2. Открой настройки расширения и импортируй **connection.json**, созданный установщиком.
3. Windows: `%LOCALAPPDATA%\AmneziaBrowser\connection.json`; Linux: `~/.config/amnezia-browser/connection.json`.
4. Открой сайт, выбери VPN. Убедись, что Chrome подтвердил PAC, затем обнови страницу.
5. Кнопка проверки в popup тестирует HTTP-выход AMNEZIA через API ядра. Для проверки настоящего SOCKS-порта запусти команду Check ниже.

Файл подключения содержит индивидуальный секрет локального API. Не публикуй его вместе с конфигом. Экспорт правил его не включает.

## Правила

Правило распространяется на домен и поддомены. Более специфичное правило имеет приоритет: `example.com → VPN`, `video.example.com → Direct`. Ещё более специфичный поддомен можно снова направить в VPN.

Direct сохраняется как явное исключение. «Удалить своё правило» возвращает наследование. Регистр, завершающая точка и префикс www нормализуются одинаково в интерфейсе и PAC. VPN для YouTube или Discord включает связанные домены из `extension/routing.js`; явное правило для того же домена переопределяет правило набора.

В настройках доступны полный список, поиск, добавление, удаление, импорт и экспорт. Импорт объединяет правила, заменяя совпадающие домены; настройки приватности из экспортированного файла автоматически не применяются. Предел — 1000 правил.

При активном PAC домены без VPN-правил идут Direct. Если VPN-правил нет или управление выключено, расширение освобождает свою настройку прокси: снова действуют настройки браузера, системы или другого расширения. При недоступном SOCKS для VPN-доменов автоматического перехода в Direct нет. Ошибка применения сохраняет выбранные правила, но показывается отдельно от успешного применения.

## Управление backend

Windows:

```powershell
& "$env:LOCALAPPDATA\AmneziaBrowser\backend.ps1" -Action Restart
& "$env:LOCALAPPDATA\AmneziaBrowser\backend.ps1" -Action Status
& "$env:LOCALAPPDATA\AmneziaBrowser\backend.ps1" -Action Check
```

Linux:

```bash
~/.local/lib/amnezia-browser/backend.sh restart
~/.local/lib/amnezia-browser/backend.sh status
~/.local/lib/amnezia-browser/backend.sh check
```

Также доступны Start/Stop/Run (в Linux — нижний регистр). Run запускает supervisor на переднем плане; Start — в фоне. В Linux пути установки нормализуются, PID supervisor проверяется вместе со временем старта, а несовместимое пространство PID выявляется до операций с процессами. Менеджер перезапускает упавшее ядро, прекращая попытки после пяти коротких сбоев подряд. Restart повторяет запуск без загрузки ядра. Status сообщает о процессе, а не о доступности VPN.

Check делает HTTPS-запрос через `socks5h://127.0.0.1:1080` к Cloudflare или Gstatic. Успех подтверждает только этот HTTP-маршрут в момент проверки. Установка может завершиться с предупреждением, если controller отвечает, а доступность сети не подтверждена.

Логи находятся рядом с ядром. Ротация работает во время записи: каждый основной файл ограничен 2 МиБ, рядом хранится один `.previous` до 2 МиБ. Более старые фрагменты удаляются при следующей ротации. Linux объединяет stdout/stderr ядра в `mihomo.log`; Windows сохраняет их отдельно. `supervisor.log` ограничен так же. Однократные ошибки запуска менеджера попадают в `supervisor-start.log` и, на Windows, `supervisor-start-error.log`. Ошибка проверки конфига сохраняется в `validation-failed.log` с ограниченным доступом; этот лог может содержать конфиденциальные данные.

Установщики проверяют конфиг до замены файлов, блокируют параллельную установку/удаление, проверяют занятые порты и пытаются восстановить прежнюю установку при сбое. Если восстановление тоже не удалось, они сообщают путь сохранённой резервной копии. В Linux откат не перезаписывает рабочие файлы, если остановка backend не подтверждена.

## Конфиги и приватность

Поддерживаются UTF-8/BOM, CRLF, комментарии `#`, регистронезависимые ключи и повторяемые Address/DNS/AllowedIPs. Остальные повторяющиеся ключи, лишние секции, неизвестные поля и shell-хуки отклоняются с ошибкой. Требуется IPv4-адрес; поддерживается максимум один различающийся адрес каждой семьи. Если конфиг содержит больше, конвертация завершается понятной ошибкой, чтобы не потерять часть адресов. Финальная проверка совместимости WG/AWG выполняется самим mihomo, включая параметры обфускации.

Диапазон `PersistentKeepalive = 25-35` допустим в AmneziaWG 3.x, но не поддерживается используемым mihomo v1.19.30. Для совместимости можно в копии `.conf` указать `PersistentKeepalive = 25`: интервал станет фиксированным, рандомизация этой настройки исчезнет. Установщик автоматически диапазон не заменяет. [Ограничение mihomo](https://github.com/MetaCubeX/mihomo/issues/3139).

DNS для целевых доменов WireGuard настроен на удалённое разрешение. Имя самого VPN-сервера может потребовать локального bootstrap DNS. При активных VPN-правилах расширение по умолчанию отключает предиктивные DNS-запросы и ограничивает непроксируемый WebRTC UDP. Эти настройки действуют на профиль и могут повлиять на звонки. Их можно отключить в настройках; ограничения или перехват политикой/другим расширением отображаются.

Это не системный VPN и не защита всех видов трафика. SOCKS5 в Chromium обслуживает TCP; голосовой UDP, DNS bootstrap и другие приложения требуют отдельных проверок. Настройки regular могут наследоваться incognito; отдельных правил для вкладки или приватного окна нет. Локальный пользователь с доступом к профилю/файлам остаётся доверенной стороной. Токен защищает controller API, но SOCKS-порт предназначен для локальных приложений и не требует этого токена. Гарантия отсутствия любых утечек не заявляется. [Chromium proxy](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md), [Chrome privacy](https://developer.chrome.com/docs/extensions/reference/api/privacy).

## Поток локального API

Файл connection.json связывает расширение с controller на 127.0.0.1:9090. Расширение отправляет заголовок `Authorization: Bearer <индивидуальный секрет>`; тело у запросов отсутствует. Неверный тип секрета отклоняется до запроса.

| Метод и endpoint | Назначение | Ответ и таймаут |
|---|---|---|
| GET /version | Версия отвечающего controller | JSON с непустой строкой version; 3 секунды |
| GET /configs | Проверка ожидаемого порта и режима | JSON: mixed-port = 1080, mode = rule; 3 секунды |
| GET /proxies/AMNEZIA/delay?url=…&timeout=6000 | HTTP-проба через выход AMNEZIA | Целочисленный delay от 0 до 65535; 7 секунд на запрос |
| GET /proxies/DIRECT/delay?url=…&timeout=6000 | Сравнение на том же URL | Такой же формат и таймаут |

Время ожидания включает чтение всего тела. Предел JSON — 262144 байта. При завершении или ошибке запрос отменяется, освобождая оставшийся сетевой поток. 401/403 отображаются как ошибка авторизации, другие неуспешные статусы — как HTTP-ошибка; неверный JSON/схема и timeout различаются. Автоматического повтора одного HTTP-запроса нет. HTTP-проба может перейти ко второму тестовому URL после сетевого отказа; ошибки авторизации и формата повторно не проверяются.

Одновременные проверки объединяются; лёгкий статус кэшируется на 5 секунд. Эти GET-запросы не меняют конфиг controller. Правила сохраняются последовательно в локальном storage Chrome и применяются через proxy API. Пробы не подтверждают посещение конкретного сайта, голосовой UDP или реальную обработку SOCKS-порта браузером. Команда backend Check проверяет отдельный путь: curl → SOCKS 127.0.0.1:1080 → AMNEZIA → тестовый HTTPS-сайт. Webhooks в этой архитектуре не используются.

## Обновления и сборка

В исходном архиве репозиторий обновлений не задан; интерфейс сообщает об этом. Для собственного выпуска:

```bash
python3 scripts/package.py --output amnezia-browser-v1.zip --version v1 --repository OWNER/REPO
```

Сборщик проверяет соответствие тега manifest, JSON, файлы страниц, права shell-скриптов и целостность ZIP; создаёт SHA-256 рядом с архивом. Версия исходников не меняется. Поле repository подставляется только в упакованный release.json. Расширение предлагает открыть новый релиз; автоматического исполнения скачанного кода нет.

## Проверки

Из корня проекта:

```bash
node --test tests/*.test.js
python3 tests/config_test.py --shell bash
python3 tests/log_test.py
python3 tests/backend_test.py
python3 tests/package_test.py
```

Для Python-тестов конфигов нужен PyYAML; для теста Linux-процессов — gcc и обычное соответствие PID процесса и /proc. На Windows запускай `python tests/config_test.py --shell powershell` и `--shell pwsh`. Потоковая обработка stdout/stderr, ротация, код завершения и timeout дочернего процесса в Windows проверяются командой `.\tests\log_test.ps1`.

Проверка ACL без запуска установщика: `.\tests\access_test.ps1 -RequireStandardUser` из обычного PowerShell. Тест использует временные файлы и функцию из настоящего `install.ps1`; проверяет права, наследование, сохранение владельца/группы, повторное применение и ошибки. В CI он запускается в обеих версиях PowerShell под учётной записью runner и под отдельным временным обычным пользователем без `SeSecurityPrivilege`. Этот CI-сценарий не выполнялся в среде подготовки архива.

`tests/smoke.cjs` проверяет загрузку расширения, настройки proxy/privacy через настоящий Chromium, освобождение прокси и скрытую карточку обновлений. Нужен Playwright 1.62.1 и его Chromium. В CI эти зависимости устанавливаются отдельно, release зависит от проверок Linux и двух вариантов PowerShell. [Запуск расширений в Playwright](https://playwright.dev/docs/chrome-extensions).

Наличие CI-сценария не означает, что все проверки уже выполнялись в каждой локальной среде.

## Удаление

1. В настройках расширения выключи «Управлять маршрутами браузера».
2. Удали расширение в `chrome://extensions`.
3. Запусти `.\uninstall.ps1` или `bash uninstall.sh` из исходной папки.

Удаляются установленные backend, конфиг, connection.json, логи и запись автозапуска. Исходный Amnezia .conf и распакованная папка проекта не удаляются. Удаление backend само по себе не отключает PAC установленного расширения.
